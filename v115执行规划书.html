这次改的是玻璃的「光学结构」

现在所有面板共用同一串变量：一层白底、一次模糊、一条顶边白线。调强度只是在加减白底的浓度，所以薄到极处仍是「雾」，厚到极处只是「更白的雾」。

v115 把面板拆成四层可独立控制的结构——受光边、镜面扫光、折射暗边、磨砂基体。强度滑杆同时驱动这四层，才谈得上「轻薄半透 → 厚重磨砂」是连续质感，而不是同一个白块换四档浓度。

受光边 Rim：左上亮、右下暗，给面板一个明确的光源方向
镜面扫光 Specular：22° 斜向高光带，随强度滑杆显现
折射暗边 Refraction：外圈 1px 冷色描边 + 柔投影，让面板浮起来
磨砂基体 Frost：白底浓度按强度分级，最薄段允许 8%

玻璃参数：旧锚点与新锚点

左列是现在的三段锚点，右列是 v115 拟采用的值。关键不是把数字调小，而是让「薄」同时意味着「更透 + 更亮的边」，而不是「更白的雾」。

现在（v114x）

P0 blur 4 alpha 12 sheen 0.20 shadow 0.20 P50 blur 12 alpha 55 sheen 0.60 shadow 0.70 P100 blur 30 alpha 96 sheen 1.50 shadow 1.60 地板 alpha ≥ 18（白天）/ 55（夜间） 特例 blur < 3 → alpha 抬到 60 面板系数 · .98 / .97 / .95 / .94

v115 拟采用

P0 blur 2 alpha 6 sheen 1.15 shadow 0.18 P50 blur 14 alpha 56 sheen 0.70 shadow 0.75 P100 blur 32 alpha 94 sheen 1.60 shadow 1.70 地板 alpha ≥ 8（白天）/ 55（夜间） 删除 blur < 3 的 alpha 硬抬 面板系数 按强度插值 .88 → .99
新增变量（由 writeVars 一并写入，随主滑杆联动） --glass-dense 0–1 面板底色系数（薄段 .88 / 厚段 .99），替代写死的 .98/.97 --glass-edge 0–1 受光边与镜面扫光强度（薄段 0.90 / 厚段 1.0，薄段反而更亮） --sb-alpha 固定 左侧图层管理专用透明度（默认 .52 / 夜间 .86） --sb-blur 固定 左侧图层管理专用模糊（默认 16px）
03

六项改造

每项按「症状 → 根因 → 方案 → 参数 → 验收」写，验收全部是可以用截图或读数判定的，不接受「看着差不多」。

1

轻薄端透明感不足

设计
症状滑杆推到最左（轻薄），面板仍是灰白雾面，看不出底图的道路与地名；用户拿到的观感是「白了但不透」，而不是「薄玻璃」。
根因三处叠加：① 白天 alpha 地板 18 把 P0 的 12 抬到 18；② blur<3 时直接把 alpha 抬到 60 的死规则；③ 面板系数 .98 几乎等于「alpha 即白底」，即使 alpha 12% 也叠成近实心。同时 P0 的 sheen 只有 .2，薄段既没厚度也没边光，视觉上就只剩「雾」。
方案P0 重定为 {blur 2, alpha 6, sheen 1.15, shadow .18}；白天地板降到 8，删掉 blur<3 → 60 硬抬；面板底色改用 --glass-dense 插值（薄段 .88）；薄段把 sheen 反向拉高，让"薄"表现为清透 + 明亮边缘。
验收滑杆 0 时，取面板中心 40×40 区域平均亮度与同位置底图亮度差 ≤ 12/255，且能透过面板辨认出底图的道路走向；滑杆 100 时该差值 ≥ 40。四档（0 / 30 / 60 / 100）截图亮度单调递增。
2

「恢复默认设置」滑杆不动、质感却变了

真 bug
症状点一下恢复默认，主滑杆还停在原来的位置，面板质感却瞬间变化；再刷新，质感又回不到「默认」，像是重置没生效。
根因重置函数只操作了三条高级滑杆（blur 14 / alpha 85 / sat 150）并调用旧的 applyGlass()，没有碰主滑杆 #set-glass，没有重算 sheen / shadow，没有写入 cd_glass72。于是 UI 与变量脱钩：滑杆显示旧值、CSS 变量已是新值。刷新时 load() 优先读 cd_glass72 的旧记录，又把变量拉回去——两个症状同一个成因。
方案收敛成单一入口 resetDisplay()：① glass = 50；② 调 applyMain() 一次写完 4 个变量 + 同步 3 条高级滑杆 + 标签文字；③ sat 回 150、节律回 5、材质包回桃花、折射回桌面默认；④ 清 cd_glass72 / cd_glass 后写入默认值；⑤ 旧 applyGlass() 保留但 reset 不再调用，杜绝双写。
验收先手动做坏状态（glass=3、alpha=30、sheen=9、材质包=夜间），点恢复默认后：主滑杆读数 50、三条高级滑杆回到 P50 对应值、材质包=桃花、饱和度 150、节律适中；刷新后全部保持；连续点 3 次无跳变、无一次「滑杆不动」。
3

边缘透光感

设计
症状面板是「一块白色矩形加了模糊」，边缘只有顶部一条发白的线，四角、左右、下沿都没有光，缺少玻璃该有的「一圈亮边把光收进来」的感觉。
根因现有边缘只有 inset 0 1px 0（顶边）与 0 0 0 .5px（极淡外描边），没有方向性（光源不分上下）、没有镜面扫光、没有外圈冷色折射边。
方案三层结构，纯 CSS、不新增 DOM：① 受光边 inset 1px 1px 0 rgba(255,255,255,.85) + inset -1px -1px 0 rgba(255,255,255,.32)（左上亮、右下暗，给出光源方向）；② 镜面扫光 伪元素 22° 斜向渐变带（宽 38%、高 130%、mix-blend-mode:screen），强度读 --glass-edge；③ 折射暗边 外圈 0 0 0 1px rgba(10,32,64,.10) + 0 12px 30px rgba(15,23,42,.10)，让面板离底图有物理距离。所有强度统一由 --glass-edge 控制，薄段给 0.9、厚段给 1.0。
验收1440 截图放大面板左上角：能看到 1px 连续亮边 + 一条斜向光带；右下边缘有轻微压暗；文字区域对比度不下降（抽样正文与背景对比度 ≥ 7:1）。夜间同样结构但边光降为冷白，不出现「白框」。
4

左侧图层管理：固定恰当质感

设计
症状左侧图层管理是常驻导航，却和设置面板共用一条实验性滑杆：把玻璃调薄，图层面板跟着变得难读；调厚，又和地图抢注意力。
根因.sidebar 的 background-color / backdrop-filter 直接引用 --glass-alpha、--glass-blur，没有任何独立令牌。
方案给侧栏一套固定令牌：--sb-alpha: .52（夜间 .86）、--sb-blur: 16px、--sb-sheen: .78，.sidebar 与 body.refraction .sidebar::after 只读这套，不再读 --glass-*。设置 / 底图 / 打点 / 图例 / 气泡卡继续跟随滑杆——它们是"实验场"，侧栏是"承重墙"。
验收滑杆从 0 拖到 100，对侧栏区域做前后两张截图的逐像素比较，平均通道差 ≤ 2%；同一时刻设置面板的亮度差 ≥ 25%。夜间滑杆全程，侧栏保持深底可读（正文对比度 ≥ 7:1）。
5

地物点：形状即语义

设计
症状学校、医院、景点、道路四类点全是同一种圆点，只靠蓝 / 红 / 绿 / 琥珀区分；小半径 + 同色描边让它们在浅色底图上偏弱；聚合气泡是纯色实心圆，和满屏玻璃面板不在同一个材质体系里。
根因LAYER_CONFIG 只有 color/radius，渲染固定为 circleMarker r5 / weight1.5 / fillOpacity .85；聚合走 DivIcon 但样式是纯色圆，没有玻璃层次。
方案改成内联 SVG 图标（形状承担语义、颜色只做辅助），统一"玻璃核"画法：1.5px 白环 + 同色半透明核 + 左上内高光 + 右下投影。缩放 ≥ 13 用图标；< 13 或开启聚合时改用玻璃胶囊气泡（白 38% + blur 10 + 数字与类别同色）。单图层 ≤ 600 个用 DivIcon，超过自动回落 CircleMarker，避免手机端掉帧。
验收1440 与 390 截图，在 100% 缩放下 3 秒内能靠形状分辨四类（而不是靠颜色）；聚合气泡与侧栏同族玻璃感；切换材质包时点位高光跟着变、但色相语义不变；夜间点位轮廓清晰、不糊在地图里。
6

全局字体与显示：对齐 iOS

设计
症状字号 11/12/13 混着用，标题和正文靠字重区分，信息层级靠感觉；圆角大小不统一；部分图标按钮热区 28–32px，手机端不好点。
根因没有 token 体系：字体栈一处定义，但字号、行高、字重、圆角、间距全部散落在各组件规则里，改一处不影响全局。
方案引入 iOS 型 token：字体栈前置 -apple-system / "SF Pro Text" / "PingFang SC"；字阶 Display 28·Title1 22·Title2 17·Body 15·Subhead 13·Footnote 12·Caption 11，行高按 iOS 比例 1.2–1.4；字重只用 400/500/600（禁 700+）；圆角阶梯 6/10/14/20/28；间距回到 8pt 网格；触控统一补到 44×44（小图标扩热区、不改视觉尺寸）；文字三档语义色 label / secondaryLabel / tertiaryLabel。动效统一 iOS 弹簧曲线 cubic-bezier(.32,.72,0,1)。
验收抽查 6 处：面板标题 22/28、正文 15/21、辅助 12/17、按钮 13/500、圆角落在阶梯值、图标按钮热区 ≥ 44。手机端逐项点击可命中；文字不溢出、不截断；与 v114x 对比无一处「字号突然变大变小」。

验收清单

每一项都要有可回看的产物（截图或读数），不接受口头「好了」。

  1. 玻璃四档：1440 桌面滑杆 0 / 30 / 60 / 100 各一张，面板中心亮度与底图亮度差按 §3-1 阈值判定单调递增。
  2. 手机端同档：390 宽滑杆 0 / 100 两张，面板不遮挡标题栏、不压左侧栏、不溢出屏幕。
  3. 恢复默认：先做坏状态再重置，主滑杆 / 三条高级滑杆 / 材质包 / 饱和度 / 节律全部归位；刷新后一致；连点三次无跳变。
  4. 侧栏固定：滑杆 0→100 前后截图逐像素比较，侧栏平均通道差 ≤ 2%。
  5. 边缘透光：面板左上角放大图能看到亮边 + 斜向光带；正文对比度 ≥ 7:1。
  6. 地物点：四类靠形状可辨；聚合气泡玻璃化；切换材质包与夜间各一张。
  7. 字体与触控：抽查 6 处字阶；图标按钮热区 ≥ 44；无文字截断与溢出。
  8. 回归：自建要素点/线/面绘制、编辑权限开关（整体 / 点 / 线 / 面）、GeoJSON 导入导出往返、删整类图层、列表三按钮图标——五项全部复测通过，不得因视觉改造回归。
  9. 性能基线（B0 存证）：改代码前先量一次，落成一张表：首屏 DOMContentLoaded、558 点灌入耗时、拖动 2 s 平均 FPS（1440 / 390）、30 次缩放后 JSHeapUsedSize。没有这张表，后面的"变快了"无法证明。
  10. 流畅度（B6 复测）：同一台机器、同一网络、同一组操作重跑，逐项对照 §7 指标——1440 平均 FPS ≥ 50、390 ≥ 40，灌入 ≤ 350 ms，换肤 P95 ≤ 32 ms，内存增长 ≤ 15%，静置 CPU ≤ 3%；并确认 preferCanvas 后点击、悬停、气泡、编辑手柄全部照常可用。
07

全局流畅性：先拆合成层，再谈视觉

视觉改造会把玻璃做得更"厚"——更多高光、更多模糊、更多边光。这些恰好都是最贵的合成操作。如果不先把性能地板抬起来，v115 上线后就是"截图很好看、手指一拖就卡"。这一节独立于视觉方案，可单独执行、单独回滚。

现状画像（实测代码，不是估算） 数据 4 个 geojson 共 235 KB；点 558 个（学校 229 / 医院 204 / 景点 125）+ 道路 15 条 渲染栈 Leaflet SVG 渲染（未开 preferCanvas），markerCluster maxClusterRadius 60 / 18 级拆散 样式栈 47 处 backdrop-filter · 4 处 SVG url() 滤镜 · 22 个 animation · 68 条 transition 11 处 drop-shadow · 6 处 will-change 结论 瓶颈不在数据量（235 KB 很小），而在"每次重绘要处理多少 SVG 节点"与"同屏叠了几层模糊"

09

需要你拍板的五件事

这五个取值直接决定观感差异与性能地板，我不替你定。回一句「A 选 2、B 选 1……」就行。

A · 玻璃强度默认值定在哪一档？

影响「恢复默认」之后的初始观感，也影响首次打开页面的第一印象。

1 · 50% 中等通透与现有文案「默认中等通透」一致，面板清晰、底图若隐若现。推荐
2 · 35% 偏透更接近 iOS 26 Liquid Glass 的观感，地图存在感更强，文字对比度略降。

B · 左侧图层管理固定成多"实"？

它是常驻导航，太透会和地图抢，太实会像一块白板。

1 · 半透玻璃 52%能透出一点底图，仍有玻璃感；夜间 86% 近实底保可读。推荐
2 · 近实底 78%几乎不透明，最稳最清晰，但会削弱整站的玻璃语言。

C · 地物点用哪种方案？

这是本轮视觉改动最大的一块，也是回归风险最高的一块。

1 · 形状语义化（学校方块 / 医院十字 / 景点花瓣 / 道路线）识别最快、最像成品；改动大，需要按 §4 的分级回落控性能。推荐
2 · 统一圆形，只重做玻璃质感与配色改动小、风险低，但四类仍主要靠颜色区分。

D · 字体要不要引入自托管近似字体？

Windows 上没有 SF Pro，纯系统栈会落到微软雅黑 UI。

1 · 纯系统字体栈零依赖、离线可用、加载最快；字形与 iOS 有差异，但比例与字重一致。推荐
2 · 自托管 Inter（约 40KB，两个 woff2）更接近 SF Pro 的骨架，代价是首屏多一次字体加载与一个缓存键。

E · 「性能模式」默认怎么定？

§7 新增的低功耗开关。定得太保守等于没做，定得太激进会削掉你想要的观感。

1 · 默认关，只按设备能力自动降级高配桌面全开（折射 + 全模糊 + 粒子）；CPU ≤ 4 核或内存 ≤ 4GB 时自动降。用户想省电再手动开。推荐
2 · 手机默认开，桌面默认关手机端直接关折射、blur 钳到 8、粒子减半；桌面全观感。
3 · 全局默认开最省电最流畅，但玻璃的"厚"会明显打折，与本次改造目标相冲。
